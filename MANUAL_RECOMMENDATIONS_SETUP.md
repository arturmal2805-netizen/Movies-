# Подключение кнопки «Подобрать фильм +»

Кнопка запускает `.github/workflows/recommendations.yml` через Supabase. Пользователь должен войти в аккаунт. Браузер не получает токен GitHub и не передаёт чужой user_id: владелец запроса определяется сервером.

## Однократная настройка

1. Откройте https://github.com/settings/personal-access-tokens/new. Создайте fine-grained token: владелец `arturmal2805-netizen`, только репозиторий `Movies-`, Repository permissions → **Actions: Read and write**. Остальные разрешения не добавляйте. Название, например `nightshift_manual_recommendations`. Укажите срок действия; после его истечения токен надо заменить в Vault.
2. Откройте https://supabase.com/dashboard/project/tecntqujshynuttfdxhx/sql/new. Выполните весь файл [supabase/manual-recommendations.sql](supabase/manual-recommendations.sql). Существующая `supabase/schema.sql` уже должна быть установлена. Повторное выполнение безопасно.
3. В том же SQL Editor выполните отдельно, заменив только placeholder значением токена:

```sql
select vault.create_secret(
 'PASTE_GITHUB_TOKEN_HERE',
 'nightshift_github_actions_token',
 'Nightshift manual Actions dispatch'
);
```

Токен вводите только в Supabase, не в код сайта, GitHub Variables или чат. Если секрет уже существует, измените его в Vault вместо создания второго с тем же именем. Если расширения отключены, включите `pg_net` и `supabase_vault` в Database → Extensions и повторите SQL. После установки API может потребоваться короткое время на обновление схемы.

## Проверка

Войдите на сайт и нажмите «Подобрать фильм +». Состояние сменится с отправки запроса на очередь, затем выполнение. После завершения появится фактическое «Добавлено +N» и обновится коллекция. `+0` означает завершённый поиск без новых подходящих фильмов. Ссылка «Открыть запуск» появится, когда GitHub начнёт работу. Перезагрузка страницы продолжит ожидание. После завершения можно сразу запустить новый поиск.

В GitHub Actions ручной `Run workflow` имеет `manual=true` по умолчанию. Поля `request_id` и `user_id` оставляйте пустыми для обычного запуска из GitHub; тогда подбор выполнится для всех профилей. Сайт отправляет только идентификатор своего запроса, а worker читает его владельца из Supabase.

## Ограничения и диагностика

Ручной запуск обходит завершённый час и скользящий почасовой бюджет. Он сохраняет дедупликацию, фильтры качества и предел 100 фильмов на один запрос; базовая цель 15, меньше 15 тоже сохраняются. Ручной поиск не сдвигает автоматическое расписание и не расходует его бюджет. В процессе одного запроса повторные клики переиспользуют активный запуск.

Общего таймера завершения в браузере нет. GitHub Actions имеет технический предел 6 часов. Предел одного сетевого обращения к Supabase — 15 секунд; временные сетевые сбои не отменяют поиск. Отказ GitHub отображается как ошибка. Проверьте срок действия токена, доступ к Movies- и Actions: Read and write. Ошибка workflow отображается отдельно; уже записанные фильмы сохраняются.

Локально проверены логика worker, браузерное ожидание и PostgreSQL RPC/RLS с подставной сетью. Настоящий вызов GitHub из Supabase требует настройки выше и отдельной проверки после неё.
