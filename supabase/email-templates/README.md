# Письмо с кодом вместо ссылки

Отправку OTP сайт уже запрашивает через `/auth/v1/otp`. Вид письма управляется в Supabase: код и magic link используют тот же endpoint. Изменением JavaScript невозможно заменить шаблон чужого почтового сервиса.

Откройте Supabase → **Authentication → Emails → Templates** (в старом интерфейсе **Email Templates**).

В **Magic Link**:
- Subject: `Код входа в Nightshift`.
- Body: весь HTML из `code.html`. Обязательная переменная — `{{ .Token }}`. Ссылку с `{{ .ConfirmationURL }}` уберите.
- Нажмите **Save**.

Повторите для **Confirm signup**, чтобы первый вход новых пользователей также присылал код. Не меняйте остальные шаблоны сброса пароля или смены email.

На сайте нажмите «Получить код», откройте новое письмо (старые письма не изменятся), вставьте цифры и нажмите «Войти» либо Enter. В Supabase Email provider можно настроить срок действия OTP; срок действия кода не равен сроку входа.

Сессия теперь хранится в localStorage и автоматически обновляется refresh token. Она сохраняется между перезапусками браузера. Старые сессии sessionStorage автоматически переносятся. Параллельные запросы разделяют обновление; вкладки используют Web Locks, если браузер их поддерживает. Ошибка сети не стирает вход. Выход и отозванные сервером credentials очищают локальную сессию.

Не выставляйте срок JWT на год: короткий JWT обновляется автоматически. Для длительного входа в **Authentication → Sessions** не задавайте короткий **Time-box session** или **Inactivity timeout**, если эти параметры доступны в вашем тарифе. Сервер может отозвать сессию; очистка данных сайта/приватный режим также требуют нового входа. Сохранение на фиксированный год клиент обеспечить не может.

Встроенный SMTP Supabase имеет ограничения адресатов и частоты отправки. Для публичного сайта используйте свой SMTP в настройках Email. Письма по-прежнему отправляет Supabase; шаблоны/SMTP требуют настройки в вашем проекте и не применяются при обычной публикации GitHub Pages.
