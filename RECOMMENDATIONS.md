# Почасовой персональный подбор

GitHub Actions → **Nightshift — подбор фильмов каждый час** → задание **Hourly personalized recommendations**.
Прямая ссылка: https://github.com/arturmal2805-netizen/Movies-/actions/workflows/recommendations.yml
Расписание: на 17-й минуте каждого часа UTC; GitHub может задерживать запуск.
Подбор запускается отдельным workflow, независимо от обновления постеров и публикации Pages. Изменения кода подбора в main запускают проверку и подбор автоматически.
Для первой проверки нажмите **Run workflow** (ветка `main`).

## Подключение

В GitHub репозитории откройте **Settings → Secrets and variables → Actions**:

- Адрес вашего Supabase уже указан в workflow. При смене проекта его можно переопределить во вкладке **Variables**, создав `SUPABASE_URL`.
- Во вкладке **Secrets → New repository secret**: имя `SUPABASE_SERVICE_ROLE_KEY`. Значение берётся в Supabase **Project Settings → API Keys → Legacy API Keys → service_role**. Также поддерживается новый серверный Secret key `sb_secret_…` (имя GitHub Secret остаётся `SUPABASE_SERVICE_ROLE_KEY`). Это приватный серверный ключ, не публичный `sb_publishable_…`. Не присылайте его в чат и не записывайте в файлы репозитория.
- Для Trakt добавьте Secret `TRAKT_CLIENT_ID` — Client ID приложения Trakt. Client Secret и вход в Trakt не нужны: используются публичные `/movies/trending` и `/movies/popular`.
- Существующие Secrets `TMDB_ACCESS_TOKEN` и `OMDB_API_KEY` оставьте.

Войдите на сайте и перенесите старые оценки: задание читает `profiles`, `ratings`, `collection` из Supabase. Пользователь без оценок получает честно подписанную стартовую подборку. После успешного запуска новые строки появятся в Supabase **Table Editor → collection**, а на сайте — при следующей синхронизации (раз в 5 минут) или обновлении страницы. Причина рекомендации хранится вместе с карточкой.

Если конфигурация отсутствует, задание завершится ошибкой с названиями отсутствующих переменных. Значения ключей не выводятся. Успешный импорт обычного каталога сам по себе не подтверждает работу персонального подбора.

## Правила

- Trakt: до 20 трендовых и 20 популярных фильмов, объединение по `ids.tmdb`, проверка деталей через TMDB. Пропускаются записи без корректного TMDB ID. Сбой Trakt не останавливает работающий TMDB. При допустимых кандидатах из обоих источников текущий лимит — до **7** фильмов в час.
- Кандидаты TMDB Discover: общий пул и пул любимых жанров, до четырёх страниц.
- Вкус рассчитывается по жанрам оценённых фильмов, двум шкалам и общему впечатлению. Это жанровая модель; анализ актёров, режиссёров и содержания пока не реализован.
- Исключаются оценённые, отклонённые, уже добавленные, стартовый каталог, фильмы без постера, ещё не вышедшие, adult и фильмы с недостаточным числом голосов.
- Среди допустимых кандидатов выше стоят совпадения с вкусом; рейтинг и популярность TMDB уточняют порядок. Полная карточка проверяется перед записью.
- OMDb добавляет рейтинг IMDb, когда он доступен. Ошибка OMDb не удаляет рекомендации; неизвестные рейтинги не выдумываются.
- По умолчанию до **5** фильмов за последние 60 минут. Дополнительный источник, давший допустимых кандидатов, увеличивает лимит на **2**, общий предел **50**. Если подходящих фильмов меньше, добавляется меньше.
- Повторы между источниками объединяются по TMDB ID. Источники происхождения сохраняются в `metadata.discoverySources`.
- Повтор после частичного сбоя учитывает уже записанные строки. Вставка с `ignore-duplicates` не перезаписывает коллекцию пользователя. Расписание сериализовано concurrency-группой workflow.
- Чтение всей истории постраничное. Приватные оценки и рекомендации никогда не коммитятся в публичный GitHub.
- Временные ошибки чтения API повторяются до трёх попыток. Источники изолированы; отказ всех источников — ошибка задания. Существующая коллекция сохраняется.

## Добавление API

Лимиты и список источников: `config/recommendations.json`. Адаптеры: `scripts/recommendation_sources.py`.

1. Напишите адаптер, возвращающий кандидатов с каноническим **TMDB ID** и полями TMDB Discover. Для IMDb ID сначала нужен поиск соответствующего TMDB ID. Название фильма или номер из другой базы нельзя использовать как TMDB ID.
2. Зарегистрируйте адаптер в `ADAPTERS`, добавьте источник с уникальным `id` в конфигурацию и включите `enabled`.
3. Ключи держите в GitHub Secrets, передавайте через `env` задания. В конфигурации храните только имя переменной.
4. Проверьте дубликаты, отказ API и бюджет тестами перед включением.

Готов мост `tmdb_id_feed`: HTTPS API возвращает `{ "tmdb_ids": [123, 456] }`. Отключённый пример `future_feed` в конфигурации можно включить после подключения настоящего сервиса. Для него предусмотрены Variable `MOVIE_FEED_URL` и Secret `MOVIE_FEED_TOKEN`. Каждая запись получает детали через TMDB. Это расширение для будущего API, а не уже подключённый Netflix/Shudder. Метаданные OMDb не увеличивают лимит: это обогащение, а не поиск новых кандидатов.

Количество новых фильмов растёт только до настроенного максимума, а не без ограничений. При росте числа пользователей понадобится очередь и другой планировщик: текущий GitHub job ограничен 20 минутами. Бесплатные API имеют квоты; GitHub и бесплатный Supabase не гарантируют точного времени или непрерывной доступности.

Проверки: `npm test`; `python3 -m unittest discover -s scripts -p 'test_*.py'`.
