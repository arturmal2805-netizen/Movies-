# Серверные оценки и персональный подбор

Публичные настройки проекта записаны в `server-config.js`. Для почасового задания требуются отдельные серверные настройки GitHub Actions (см. `RECOMMENDATIONS.md`). Новые оценки сохраняются только после подтверждения Supabase; при отказе сервера окно остаётся открытым. Старые browser-оценки не удаляются до успешного явного переноса.

1. Создайте бесплатный проект на supabase.com. Пароль базы сохраните у себя.
2. SQL Editor → New query: выполните `supabase/schema.sql`. Включены RLS-политики: каждый вошедший пользователь видит и меняет только собственные данные. Анонимный доступ к оценкам и коллекциям запрещён.
3. Authentication → Providers → Email: включите вход по email. Authentication → Emails → Templates: замените Magic Link и Confirm signup на шаблон `supabase/email-templates/code.html` и сохраните. Подробности в `supabase/email-templates/README.md`. Основной вход — по коду. Сессия сохраняется между закрытиями браузера; поддержка старых ссылок сохранена. Authentication → URL Configuration: Site URL и Redirect URLs должны включать https://arturmal2805-netizen.github.io/Movies-/ вместо localhost. Письма встроенного почтового сервиса могут быть ограничены адресами участников проекта; для других пользователей настройте свой SMTP.
4. Project Settings → API/Data API: получите Project URL. В API Keys возьмите публичный Publishable key (или legacy anon). Впишите только эти публичные данные в `server-config.js`. Не используйте там Secret key, service_role или пароль базы.
5. GitHub → Settings → Secrets and variables → Actions: создайте **Variable** `SUPABASE_URL` и **Secret** `SUPABASE_SERVICE_ROLE_KEY` (legacy service_role key; не anon). Оставьте существующие `TMDB_ACCESS_TOKEN` и `OMDB_API_KEY`. Секретный ключ нельзя публиковать, присылать в чат или вводить в браузер сайта.
6. После публикации: «Войти», email, код из письма. При наличии старых оценок нажмите «Перенести старые оценки на сервер». Проверяйте вход на втором устройстве, сохранение оценки, её появление в архиве и сохранность после очистки браузера.
7. Actions → Nightshift — подбор фильмов каждый час → Run workflow. Независимое задание Hourly personalized recommendations добавляет по умолчанию до 3 фильмов каждому аккаунту, для которого прошёл час. Расширение источников и лимитов описано в `RECOMMENDATIONS.md`. Оценки и коллекция записываются только в Supabase, не в публичные JSON GitHub. Кандидаты берутся через TMDB Discover, исключаются все ранее добавленные, оценённые и фильмы стартового каталога. Используются жанровые предпочтения, выведенные из съёмки, сюжета и общего впечатления. Причина видна на карточке. Popcornmeter по-прежнему не импортируется.

Непрерывность не гарантируется бесплатным тарифом или расписанием GitHub: задания могут задерживаться, проекты Supabase приостанавливаться. В браузере синхронизация каждые 5 минут; hourly job использует UTC, а задержка запуска не добавляет пропущенные пачки. Настроенный лимит за предыдущие 60 минут учитывает частично завершённые запуски. Живые Auth/RLS и почтовая доставка требуют проверки после создания проекта.

Проверки: `npm test` и `python3 -m unittest discover -s scripts -p 'test_*.py'`. Не запускайте текущие browser-тесты старой локальной системы оценок: новый сценарий требует аккаунт и успешную серверную запись.

Ручной запуск GitHub через кнопку «Подобрать фильм +»: [настройка Supabase RPC и Vault](MANUAL_RECOMMENDATIONS_SETUP.md).
